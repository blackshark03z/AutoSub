# One-Slice Worker Task Contract — Kit v1.2.2

**Purpose:** single handoff per evidence-led critical-path slice; no iterative Owner relay for ordinary file/test/log collection. This is a template, not an already approved new WP or permission to start a worker.

## Start-of-task contract
- **Milestone:** one bounded part of Owner-approved AutoSub Cloud source URL → downloadable en-US MP4 journey. State its concrete product delta and why the currently observed blocker prevents it.
- **Identity:** exact worktree path + branch + baseline HEAD + target file/module surface. Worker must fail-closed on unexpected dirty changes/conflicting HEAD; never silently choose an arbitrary repo.
- **Inputs/evidence:** actual Source URL/test fixture identity and checksums where permitted; prior report path/HEAD; existing relevant interfaces to reuse. No credentials or signed URLs in docs/prompts.
- **In scope:** explicit behavior to connect/fix, artifact/result contract, accepted reuse candidates. Worker owns implementation HOW; coordinator should not micromanage script names, commits or redundant checkpoints.
- **Out of scope:** unrelated UI redesign, alternate provider/platform, full-film download if not approved, speculative queue/orchestrator, broader model downloads, merge/push/deploy/publication.
- **Permissions:** local file/Git commits only for owned worktree when granted; network/footage/installer/provider limits in exact numbers from Owner approval; no implicit privilege from tool access.
- **Time/space/cost/stop:** stated maximum runtime, disk and download limits if approved; bounded retries; supervised vs unattended explicitly; no-progress abort and clean cancellation.
- **Acceptance oracles:** real-input expected output with cue/translation counts, audio/logo/AI-badge preservation, checksum/provenance, checkpoint recovery, focused tests, required full/protected at candidate, honest editorial/security/publication state. Product PASS requires cloud source-link→retrievable artifact proof, not a local fixture.
- **Output location:** commit only if authorized; report in existing docs/research or owned run folder with exact path, source hash, branch+HEAD, tests actually run and evidence file names. Tech lead re-reads via MAR, so Owner need only relay the one initial task when no direct worker channel is approved.

## Return format (one short report)
1. `HEAD / files / exact command or run ID` with evidence-backed result.
2. `TECHNICAL / CLOUD_PRODUCT / EDITORIAL / SECURITY / PUBLICATION` status separately.
3. The first remaining blocking gate and its reproduction; other speculative enhancements deferred.
4. `COMPLETE_VERIFIED`, `PARTIAL_DELIVERY` or `BLOCKED` with reason; never 'done' because pytest is green.
