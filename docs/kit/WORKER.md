## Kit execution (SHAPE → BOUND → SLICE → BUILD → PROVE → LEARN)
- **SHAPE** the actual milestone and one representative user journey; do not treat one subtask or test as the product goal.
- **BOUND** exact allowed paths, source/media identity, non-goals, exit criteria, money/network/disk/time gates. If no numeric owner-approved limit exists, do not invent a larger allowance.
- **SLICE** choose the smallest product-critical-path change backed by observed evidence. Reuse → wire → fix → replace/delete → add. No parallel new subsystem when the existing one can be connected.
- **BUILD** focused/risk-sensitive tests at useful checkpoints. Do not rerun the full test suite after every edit; do not bypass protected tests or change acceptance to fit implementation.
- **PROVE** the composed user journey on a real source/configuration; run required/full/protected checks for the exact release candidate. A 6-minute local pilot is TECHNICAL PASS evidence, **not Cloud Product PASS** or owner publication permission.
- **LEARN** update existing report/state with code HEAD, exact commands and outcomes, artifacts/hash/provenance, remaining blocker, product delta and honest COMPLETE_VERIFIED / PARTIAL_DELIVERY / BLOCKED. Two failed attempts: change diagnosis; two work cycles without product progress: reassess scope; never loop indefinitely.
