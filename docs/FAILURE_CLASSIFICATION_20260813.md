# Failure classification: 2026-08-13

The clean-checkout baseline reproduced 26 failures with `python -m pytest -q`.
They were all assertions against retained historical project outputs or
release/package outputs that are intentionally excluded from Git (`data/` and
`release/` are ignored). None exercised a current product code path with a
supported current fixture, so no failure is class E.

The existing test architecture now labels these checks `pytest.mark.release`.
Normal regression uses the default `-m "not release"`; release validation is
explicitly executable with `python -m pytest -m release` after its documented
bootstrap/build prerequisites. The marker is a gate, not a skip or xfail: the
assertions remain unchanged and still fail when the required release inputs are
absent or invalid.

## Provenance and supported bootstrap

- **CP07** is the retained development-project lineage consumed by
  `app/services/operator_ui.py` (`vertical_slice_cp07`). Its CP07A summary,
  canonical timeline, and accepted preview are generated files under
  `data/projects/vertical_slice_cp07`; the repository contract deliberately
  excludes that machine-local media. The operator tests therefore remain in
  release validation rather than manufacturing a fake video fixture.
- **CP08F** is generated by
  `tools/run_cp08f_targeted_recomposition.py`. It reads the CP08F selective
  render plus `cp08f_non_dialogue_text_events.json`, verifies the immutable
  base hash `870b44f25b1b3366b0532f40162608193263e5504b5c787b9a1fc8280fc879a7`,
  and writes the targeted manifest/render and evidence under CP08F.
- **CP09** is the production golden-path dry-run implemented in
  `app/services/production_golden_path.py`. It imports the CP08G artifact only
  after the canonical hash `37394ab6ce036abdbebb6e7d9cebc8d3dc2661adae1324f0b635184042589646`
  is verified, then deterministically creates CP09B export packages and CP09C
  closeout evidence.
- **CP12B** is generated by `tools/build_cp12b_full_portable.py` from the
  CP11A application package and CP11C OCR add-on after source-hash and disk
  preflights. Its output is intentionally not committed as a bulky historical
  ZIP.
- **CP13A** / **CP13A1** are generated by
  `tools/build_cp13a_one_click_beta.py` and
  `tools/build_cp13a1_complete_payload_hotfix.py`, respectively. They wrap the
  CP12B baseline and require release-local runtimes/FFmpeg and the Windows
  IExpress toolchain; protected hashes and external-machine evidence remain
  release acceptance inputs, not normal product fixtures.

No fixture was restored and no product code was changed: the supported
mechanisms already exist, and the defect was test-suite inclusion of release
validation, not application behavior.
